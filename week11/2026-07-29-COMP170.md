## Cleaning Up Yesterday's Messy Code

On our last class of the term, we went back to the word-counting program we wrote yesterday and admitted it was hard to read — everything crammed into one long stretch with no clear beginning, middle, or end. We pulled two pieces out into their own named pieces of code: one that answers "have I seen this word before, and if so, where?" (returning $-1$ when the answer is no), and one that uses that answer to either add a new word or bump an existing count up by one. This shrank a tangled block of about twenty lines down to two short lines that were much easier to follow.

## A Better Way to Keep Count: the Dictionary

We then set the two side-by-side lists aside entirely and rebuilt the same counting program using a new way of storing information: a dictionary, which pairs each word directly with its own count instead of relying on matching positions in two separate lists. Checking whether a word was already there, and updating its count, each became a single short line. Running it, we noticed that asking for the count of "times" failed even though the word clearly appeared in the text — because commas were still attached to some words, so "times," and "times" were being counted as different words.

## Fetching a Book from the Internet

We looked at how to read a book straight from a website instead of a file already saved on our computer, using a Python tool called `urllib.request` to grab the text from a web address. Because reading the whole book into one giant chunk of text could use more memory than some computers have available, the last assignment asks us to read the book from the web one line at a time, counting words into a dictionary just as we did today.
